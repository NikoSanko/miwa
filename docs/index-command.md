# 索引を保つ（`index`）

## なぜ索引か

仕様の文書が増えると、LLM にすべてを読ませることはできませんし、人にとっても探すのが大変になります。そこで miwa は、`docs/index.md` のような **索引** を根にした木をたどって、必要な文書だけをその都度読む読み方を支えます（[PageIndex](https://github.com/VectifyAI/PageIndex) と同じ考え方です。PageIndex は、PDF を木構造の索引にして、LLM がノードごとに「この下を開くか」を判断しながら辿る手法で、miwa はそれを文書リポジトリに当てはめています）。

```
docs/index.md（根）
 ├─ 節（ディレクトリ or 見出し）: タイトル + 要約
 │   ├─ 文書: タイトル + 要約 ──▶ 本文
 │   │                          └─ 本文中のリンク ──▶ req ──▶ test
 │   └─ 文書: ...
 └─ 節: ...
```

読み手は各ノードで「この下を開くべきか」を **タイトルと要約だけ** で判断し、開いた先でまた同じ判断を繰り返します。たどった経路がそのまま出典になります。フォルダ名は信頼できる手がかりとは限らないので、ディレクトリにも要約を付けます。

miwa が保証するのは、索引が文書と食い違っていないこと（形式・網羅・一致）です。要約が良い要約かどうか、文書の分け方が妥当かどうかは見ません。

## 索引の形式

索引は `index.md` という名前のファイルで、次のような箇条書きの **エントリ** を並べます。子ディレクトリの `index.md`（例では `guides/index.md`）には、フロントマターでそのディレクトリのタイトルと要約を書きます。

```markdown
---
title: 仕様の下位ディレクトリ
description: 利用者向けの手引き
---

# 手引きの索引
```

親の索引は次のようになります。

```markdown
# 仕様の索引

## 使い方

- [更新漏れを検知する（check）](check.md) — 3 層のどこが追随していないかを機械的に見つける。
- [仕様の下位ディレクトリ](guides/) — 利用者向けの手引き
```

- **エントリ**: 箇条書きの項目のうち、[内容がリンクで始まるもの](../req/index-entry-detection.md)です。`-` `*` `+`、順序付き、入れ子のどれでもかまいません。太字で包んだリンクやタスクリスト、段落の途中のリンクはエントリとして数えません。
- **タイトルと要約**: リンク文がタイトル、リンクの後ろが要約です。[要約は区切り記号（`-` `–` `—` `:` のいずれか。省略可）を除いた残り](../req/index-entry-description.md)で、複数行にわたっていても 1 つのエントリです。
- **文書エントリ**: リンク先が文書（フロントマターに `type` を持つ Markdown）のエントリです。タイトルは文書の `title`（無ければ最初の見出し、それも無ければファイル名）、要約は文書の `description` です（[詳細](../req/index-document-title-and-description.md)）。
- **ディレクトリエントリ**: リンク先がディレクトリ（`sub/`、`sub`、`sub/index.md` のいずれの書き方でも可）のエントリです。そのディレクトリに `index.md` が必要です。ディレクトリのタイトルと要約の正（SoT）は、その子 `index.md` のフロントマターの `title` / `description` です（[詳細](../req/index-document-title-and-description.md)）。タイトルは `title` が無ければディレクトリ名になり、要約は `description` が無い・空・改行を含むときは無しとして扱います。エントリのリンク文と要約はこれと照合され、`miwa index` が子 `index.md` から書き写します。なお、OKF §8 は `index.md` にフロントマターを置かないとしているため、`index.md` が `okf_version` 以外のキー（`title` / `description`）を読む点は OKF から少し外れます。`index.md` 自身は、フロントマターがあってもノードにも文書にもなりません。
- **リンク先の読み方**: 外部 URL は無視します。`/` で始まるパス、索引の根の外へ出るパス、索引自身や祖先のディレクトリを指すリンクは「壊れたエントリ」になります。`#` 以降は取り除き、`%20` などのパーセントエンコードは元に戻して解決します（[解決の規則](../req/index-link-resolution.md)）。
- **節見出し**（`##` など）や前書きは人の領分です。miwa は検査も生成もしません。

### 担当範囲と入れ子

索引は 1 つだけでも、ディレクトリごとに置いてもかまいません。ある索引が列挙すべき文書（担当範囲）は、[その索引のディレクトリ配下の文書から、自前の `index.md` を持つ子孫ディレクトリ配下のものを除いたもの](../req/index-ownership-and-nesting.md)です。子孫ディレクトリに `index.md` を置いたら、親の索引にそのディレクトリを指すディレクトリエントリを書きます。

`index.md` と `log.md` は予約名で、[`type` を書いていても doc や req として扱いません](../req/index-reserved-names.md)。`log.md` は OKF §9 の変更履歴ファイル（日付見出しの下に箇条書きを並べる）です。miwa はノードにも文書にもせず、索引の対象（`NotListed` / `UntypedFile`）からも外し、それ以外に読み書きしません。

## `check` が見るもの

`index` を設定すると、`check` は次を `index` 種別の finding として報告します（reason の一覧は [check](check.md) を参照）。

- 索引が無い、文書が索引から漏れている、`type` のないファイルが木から消えている
- エントリのリンク先が無効、リンク文や要約が文書（ディレクトリエントリでは子 `index.md`）のタイトル・要約と違う
- 文書の `description` が無い、子ディレクトリの `index.md` に `description` が無い、子の索引が親から辿れない

## `miwa index`: 索引を文書から更新する

人が文書のタイトルと要約を索引へ書き写す必要はありません。`miwa index` が索引を文書から更新します。人がするのは、追加された行を適切な節へ **移す** ことと、子 `index.md` の `description` を書くことだけです。

```
miwa index
```

### 変えるもの

- [既存の文書エントリのリンク文と、リンクの後ろ（区切りと要約）](../req/index-command-rewrites-entries.md)を、文書のタイトルと要約に書き換えます。区切りは既存のものを保ち、無ければ `—` を使います。ディレクトリエントリも同じ規則で、子 `index.md` のフロントマターの `title`（無ければディレクトリ名）と `description` に書き換えます（子に要約が無ければ区切りと要約を付けません）。同じ文書を指すエントリが複数あれば、すべて書き換えます。タイトルに含まれる `[` `]` は `\[` `\]` にエスケープします。折り畳み参照（`[T][]`）とショートカット参照（`[T]`）のエントリは、リンク文が参照ラベルを兼ねるためリンク文を書き換えず、要約だけを更新します（`TitleMismatch` が残るので人が直してください）。複数行にわたっていたエントリは 1 行に畳まれます（そのため、`check` が何も報告しない状態でも `updated` になることがあります）。
- [担当範囲にあるのに列挙されていない文書](../req/index-command-appends-missing.md)を、ファイルの **末尾** にパス順で追加します。人はその行を適切な節へ移してください。親から辿れない子の索引は、`- [<ディレクトリのタイトル>](<相対ディレクトリ>/) — <要約>` の形で末尾に追加します（子 `index.md` に要約が無ければ区切りなしです）。改行コードは既存のファイルに合わせ（CRLF なら CRLF）、`description` が無い文書は区切りと要約を付けません。
- [リンク先が存在しない文書エントリの行を削除](../req/index-command-removes-missing-targets.md)します。その行の入れ子の子項目は削除されず、直前の項目の下に残ります。除外ディレクトリ配下を指すエントリや、`type` のないファイルを指すエントリは削除しません。
- [索引が無ければ新規に作ります](../req/index-command-creates-flat-list.md)。担当範囲の文書をパス順に平坦に並べ、見出しは作りません。

### 変えないもの

[エントリ行以外のバイト列（前書き、節見出し、エントリの並び順、入れ子の子項目、BOM、改行コード）は変えません](../req/index-command-preserves-and-exits.md)。リンク先（`](…)` の中身、参照形式の定義、title 属性）も書き換えません。出力は決定的で、続けて実行すると 2 回目は変更なしです。

実行すると、索引ごとに `created <path>` / `updated <path>` / `unchanged <path>` を 1 行ずつ表示します。`index` が未設定のときはエラー（exit 1）です。実行後に残る finding は、人の判断が要るもの（`MissingDescription`、`MissingDirectoryDescription`、`UntypedFile`、文書でないファイルを指す `BrokenEntry`）だけです。

## LLM の読み方

LLM（AI エージェント）には、プロジェクトの `AGENTS.md` / `CLAUDE.md` から、次の手順を参照させてください。

1. `docs/index.md` を読む。各エントリのタイトルと要約だけで、質問に関係しそうな節・文書を選ぶ。
2. ディレクトリエントリなら、その `index.md` を開いて 1 に戻る。文書エントリなら本文を読む。
3. 本文中の req へのリンク文で、関係する req を選んで読む。req から test に辿るときは、`check --format json` の `test-req` エッジか、テストコードの `[req id]` マーカーを使う。
4. たどった経路（索引 → 文書 → req → test のパス）を出典として示す。
