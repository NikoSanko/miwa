---
type: Requirement
id: FR-112
---
`miwa site --diff` は、変更前と変更後の文書（`type` を持つ Markdown）を、次の順で対応づける。文書の分類は、doc（`type: BusinessNeed`）、req（`type: Requirement`）、一般文書（それ以外の `type`）の 3 つとする。

1. 両側で `id` を持つ文書は、（分類, `id`）が同じものを同じ文書とする。分類が違えば `id` が同じでも別の文書である（`type` を分類をまたいで変えた文書は、削除と追加になる）。パスが違えば移動とする。
2. 少なくとも一方の側で `id` を持たない文書は、反対側の、同じパスで同じ分類の文書と対にする。git のリネーム検出は使わない。
3. 対にならなかった文書は、変更前だけにあれば削除、変更後だけにあれば追加とする。

次のいずれかに当たるときは、エラーとして何も書かず、exit 1 を返す。該当する文書は、全件を探してから止まる。
- 変更後の側で `id` を持たない文書のうち、差分の対象になるもの（FR-111）。
- 変更前に `id` があったのに、変更後で `id` が無くなった文書。

変更前の側だけで `id` が無い文書は、エラーにしない。同じパスの相手が無ければ、削除として出す。両側で `id` が無く内容が変わらない文書と、`id` を足しただけの文書（同じパスで対になり、内容が同じ）は、対象にならずエラーにもならない。`id` の追加と本文の変更を同時にした文書は、同じパスで対になり、変更として出る。

この検査には、公開ページの集合とは別に、設定の `docs` と `requirements` の配下で `type: BusinessNeed` または `type: Requirement` を持つ Markdown を、`id` の検証前の状態で候補に加える。`id` が無い・不正で Graph のノードにならない doc と req も含める。索引の根の外にある req の `id` を消したときも、削除として扱わず、エラーにする。

エラーのメッセージは標準エラーへ、次の形で出す。

```
documents in the diff have no id; add "id:" to their front matter:
<リポジトリ相対パス>
...
```

2 行目以降は 1 行に 1 パスで、パスの順に並べる。

同じ側の公開文書の中で、同じ分類かつ同じ `id` の文書が複数あるときは、その文書が差分の対象かどうかにかかわらず、exit 1 を返す（対応づけが一意にならないため）。doc と req の重複は、`check` の DuplicateId と同じ状態である。
