エッジのハッシュの出所はエッジ種別ごとに定める。`desc` エッジの `from` は、ノードの要約（FR-071 と同じ正規化: フロントマターの `description` を YAML の文字列値として解釈し前後の空白を除いたもの。無い・空・改行を含む場合は空文字列）のハッシュ、`to` は本文（フロントマターを除く。FR-002）のハッシュとする。ハッシュは既存の規則どおり SHA-256 で、改行コードの違いは LF に正規化して無視する。`doc-req` と `test-req` のハッシュの出所は変えない（FR-002 など）。したがって `description` だけを変更しても、`doc-req` と `test-req` のハッシュは変化せず、それらのエッジに finding は出ない。`judge` が `desc` エッジについて Jev に渡す内容も同じ出所とし、要約には要約（正規化後。無ければ空文字列）、本文には本文（フロントマターを除く）を使う。
